# Distributed Multi-Sensor Monitoring for Gas Pipelines — TeDKF Research Prototype

A runnable local research project inspired by **Trust-Enhanced Distributed Kalman Filtering for Sensor Fault Diagnosis in Sensor Networks** (Shaheen, Chawla and Salvo Rossi, IEEE TSIPN 2025, DOI: [10.1109/TSIPN.2025.3606167](https://doi.org/10.1109/TSIPN.2025.3606167)).

> **Research and safety warning:** The uploaded paper evaluates a **four-dimensional thermal system**, NOT a validated natural-gas pipeline hydraulic model. This repository reproduces the *method structure* on original synthetic teaching data. It must not be used for pipeline control, safety alarms or operational decisions.

## Implemented method

- A local Kalman predictor and covariance at each sensor, using the paper's 4×4 thermal state transition matrix with H=I and Q=0.05I.
- Innovation-only exchange: sensor residuals y_i = z_i − H x_i prior.
- IDB-inspired incremental trusted-cluster selection: mutual reachability, minimum detection score and adaptive threshold = mean(scores) + lambda; seeded by an initially healthy snapshot.
- Reliable innovation fusion: average only trusted residual vectors, then local posterior state update using local Kalman gains.
- Deterministic synthetic sensor-fault scenarios: **bias, drift, noise, stuck** (see `tedkf/simulation.py`).
- Diagnostics, trust decisions, reconstruction/state-estimation error evidence and tests.

See [method-to-code mapping](docs/methodology.md) for the exact differences from the publication. The published numerical results have not been reproduced or independently validated.

## Data engineering and open-source dataset

`data/public/sensor_measurements.csv` contains original CC0 virtual sensor measurements and simulated fault labels (generated by `tedkf.simulation`). The pipeline validates samples, quarantines rejected observations, emits Bronze/Silver/Gold Parquet and quality metrics, and stores TeDKF decisions. No live gas pipeline measurements or personal data are included.

## Windows setup

```powershell
git clone https://github.com/Khadija162/Distributed-Multi-Sensor-Monitoring-for-Gas-Pipelines1.git
cd Distributed-Multi-Sensor-Monitoring-for-Gas-Pipelines1
py -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m tedkf.pipeline
.\.venv\Scripts\python.exe -m tedkf.runner
.\.venv\Scripts\python.exe -m pytest -q
```

Start backend and frontend in separate terminals:

```powershell
.\.venv\Scripts\python.exe -m uvicorn backend.main:app --reload
.\.venv\Scripts\python.exe -m streamlit run frontend/app.py
```

Or run Docker Desktop (includes one-shot ETL/evaluation initialization):

```powershell
docker compose up --build
```

API docs: http://localhost:8000/docs
Dashboard: http://localhost:8501

## API

- `GET /health`: status and dataset readiness
- `GET /api/summary`: ETL metrics and batch evaluation
- `GET /api/sensors`: per-sensor sample/label summaries
- `GET /api/diagnostics?limit=100`: most recent trust decisions and residual scores

## Experimental boundaries

This is a **paper-inspired centralized simulation of a distributed algorithm**, not multiple physically connected sensor processors. While each virtual sensor retains a local KF, the implementation performs shared innovation selection in one Python process. The paper's innovations are fused, not raw measurements; real-world communication topology, delay and packet-loss experiments remain future work. The threshold, R and injected fault magnitudes are explicit example choices, not calibrated gas-sensor settings.

Next research steps: real or licensed gas-pipeline hydraulic network model; genuine field sensor data with permission; fault-magnitude sweeps; SNR controls; detection accuracy/ROC and RMSE comparisons with standard DDKF; secure distributed telemetry and alert human review. No infrastructure is deployed and no operational pipeline is controlled.
